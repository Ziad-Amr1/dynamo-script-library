## Overview

This repository collects reusable automation for Autodesk Revit built with
[Dynamo](https://dynamobim.org/) and Python. Each tool lives in its own folder
with a graph and/or script, a beginner-friendly README, a changelog, and a
machine-readable `script.json` manifest.

The library is designed around two principles:

1. **Users should not need Git.** Every tool can be downloaded as part of the
   repository ZIP or as a release package.
2. **Maintenance should be automatic.** The tool catalog in this README,
   manifest validation, and release ZIPs are generated by scripts in `tools/`
   and checked by GitHub Actions.

What you will find here:

- `.dyn` Dynamo graphs for Revit workflows.
- Python scripts for Dynamo's CPython 3 or IronPython 2.7 engines, plus standalone
  utilities that can be tested outside Revit.
- Reusable resources, examples, templates, and contribution tooling.
- Documentation covering installation, downloading, versioning, and releases.

> **Status:** this repository is in its initial scaffolding phase. Only tools
> whose README explicitly states verified compatibility should be assumed to
> work with a given Revit and Dynamo version.

## Quick start for non-technical users

1. **Download the library.** Open the repository page, select
   **Code > Download ZIP**, then extract the ZIP. Direct link:
   [Download the latest `main` branch as a ZIP](https://github.com/Ziad-Amr1/dynamo-script-library/archive/refs/heads/main.zip).
2. **Find a tool.** Browse the [tool catalog](#tool-catalog) or the `scripts/`
   folder. Open the tool's `README.md` first.
3. **Check requirements.** Install any Dynamo packages listed in the tool's
   `script.json` or README. Revit and Dynamo do not bundle all packages.
4. **Open the graph.** In Revit, open **Manage > Dynamo**, then open the `.dyn`
   file. For a Python-only tool, follow the tool's usage section.
5. **Test safely.** Run the tool on a copy of your model before using it in
   production, and read the tool's warnings.

More detail, including how to download a single tool or a versioned release, is
in [docs/DOWNLOADING.md](docs/DOWNLOADING.md).


## Compatibility and requirements

No Revit, Dynamo, or Python engine version is claimed as supported unless the
individual tool README and `script.json` state that it has been verified.

| Layer | Repository-wide guidance |
| --- | --- |
| Revit | Check the tool README. The library itself does not require a specific Revit version. |
| Dynamo | Check the tool README. Dynamo 2.x and 3.x file formats are not interchangeable in all directions. |
| Python engine | Tools state either **CPython 3** or **IronPython 2.7**. CPython 3 is recommended for new tools. |
| Repository tooling | Python 3.10 or newer. Standard library only; no packages are required. |
| Git | Optional for users. Required only for developers who want to clone and contribute. |

Dependencies such as Dynamo packages are listed per tool in `script.json` and
must be installed through Dynamo's **Packages > Manage Packages** before running
the graph.

## Versioning and releases

This repository uses [Semantic Versioning](https://semver.org/):
`MAJOR.MINOR.PATCH`, where MAJOR allows incompatible changes, MINOR adds
backward-compatible functionality, and PATCH contains backward-compatible fixes.

Four different things are often confused:

| Concept | What it means here |
| --- | --- |
| **Tool version** | The version in a tool's `script.json` and `CHANGELOG.md` (for example `1.2.0`). Each tool can evolve independently. |
| **Git commit** | An immutable snapshot of the repository history. It is not a release and has no user-facing notes. |
| **Git tag** | A named pointer to a commit, such as `v1.2.0`. It marks a repository snapshot but is not itself a GitHub release. |
| **GitHub release** | A tag plus human-readable notes and downloadable assets such as tool ZIPs. |

Repository-level tags and releases use a `v` prefix (`v0.1.0`). Individual tool
packages keep their own version numbers.

Release notes live in `docs/releases/`. The release workflow only runs for tags
that match `v*`; it never publishes on every commit. See
[docs/VERSIONING.md](docs/VERSIONING.md) and [docs/RELEASING.md](docs/RELEASING.md).

## Adding a new tool

Use the scaffolder:

```powershell
python tools/new_tool.py --id my-tool --name "My Tool" --category utilities --description "What the tool does."
```

Then implement the graph or script, complete the README and manifest, run the
checks, regenerate the catalog, and open a pull request. The full workflow is in
[docs/ADDING-A-SCRIPT.md](docs/ADDING-A-SCRIPT.md).

Local checks:

```powershell
python -m unittest discover -s tests -v
python tools/validate_manifests.py
python tools/generate_catalog.py --check
python tools/package_tools.py --out dist
```

## Reporting bugs and requesting features

- **Bug:** use the [bug report form](https://github.com/Ziad-Amr1/dynamo-script-library/issues/new?template=bug_report.yml). Include the tool name and version, Revit and Dynamo versions, and reproduction steps.
- **Feature or new tool:** use the [feature request form](https://github.com/Ziad-Amr1/dynamo-script-library/issues/new?template=feature_request.yml).
- **Security issue:** do **not** open a public issue. Follow [SECURITY.md](SECURITY.md).
- **Question:** open a discussion or an issue with the `question` label.

## Security

Dynamo graphs and Python nodes execute code and can modify Revit models. Review
a tool before running it, test on a copy, and report vulnerabilities privately
as described in [SECURITY.md](SECURITY.md).
